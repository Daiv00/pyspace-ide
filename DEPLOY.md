# Деплой на Render

Задача: положить папку в репозиторий GitHub, один раз настроить Render, и дальше
любой `git push` сам обновляет сайт.

---

## 1. Залить папку на GitHub

Можно в существующий репозиторий (например `Daiv00/pyspace-ide`) или в новый.

```bash
cd pyspace-ide
git init
git add .
git commit -m "PySpace IDE 5.0"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

Если репозиторий уже существует и в нём старая версия — просто замените файлы новыми
и сделайте commit + push. Ветка должна называться `main` (она указана в `render.yaml`).

---

## 2. Создать сервис в Render (один раз)

1. Откройте [dashboard.render.com](https://dashboard.render.com).
2. **New → Blueprint**.
3. Выберите свой репозиторий с этой папкой. Render найдёт `render.yaml` сам.
4. Render покажет сервис `pyspace-ide` (Docker, план Free, регион Frankfurt).
5. Он попросит два значения, которых нет в файле (они помечены `sync: false`):
   - `PYSPACE_ADMIN_USER` — логин администратора, например `denis`;
   - `PYSPACE_ADMIN_PASSWORD` — пароль, минимум 8 символов.
   Остальные переменные, включая секрет сессии, Render создаст сам.
6. **Apply / Create resources** — начнётся сборка образа (5–8 минут в первый раз).
7. Когда статус станет `Live`, откройте адрес вида
   `https://pyspace-ide.onrender.com` и войдите под администратором.

Проверка здоровья сервиса: `GET /healthz` отвечает
`{"status":"ok","schema":1,"persistent":false}`.

---

## 3. Дальше — только push

`autoDeploy: true` уже стоит в `render.yaml`. Любой коммит в `main`:

```bash
git add .
git commit -m "правки"
git push
```

…запускает пересборку и деплой автоматически. Ничего в панели Render нажимать не надо.

---

## 4. Данные и план Free (важно)

На плане Free постоянный диск не подключается. Файловая система контейнера временная,
поэтому **при каждом деплое и при перезапуске (в том числе после «засыпания» сервиса)
база и файлы проектов обнуляются**. Пользователи, проекты и загруженные файлы исчезнут.

Внизу статус-бара IDE это видно: `диск: временный`.

Как жить с этим:
- скачивайте важные проекты кнопкой **Скачать проект (ZIP)**;
- восстановление — **Импорт ZIP в проект**.

### Включить постоянный диск (план Starter, платный)

Откройте `render.yaml`, раскомментируйте блок `disk` и смените план:

```yaml
    plan: starter          # было: free
    disk:
      name: pyspace-data
      mountPath: /data
      sizeGB: 5
```

и добавьте переменную:

```yaml
      - key: PYSPACE_DATA_DIR
        value: /data
```

После `git push` Render подключит диск, и статус-бар покажет `диск: постоянный`.

## 5. Чтобы сервис не засыпал

Бесплатный план Render останавливает сервис после **15 минут без входящего трафика**
(считаются и HTTP-запросы, и сообщения WebSocket). Следующий запрос ждёт 30–60 секунд,
пока поднимется новый контейнер.

### Встроенный самопинг (уже включён)

Модуль `app/keepalive.py` поднимает фоновый поток, который каждые 10 минут дёргает
**свой же публичный адрес** `/healthz`. Настраивать ничего не нужно: самопинг включён
по умолчанию, а адрес ищется в три приёма —

1. `PYSPACE_PUBLIC_URL`, если вы задали его сами;
2. `RENDER_EXTERNAL_URL` — Render подставляет его в сервисы, созданные по `render.yaml`;
3. **первый входящий запрос** — адрес берётся из самого запроса (с учётом заголовков
   `X-Forwarded-Proto` и `Host` от прокси Render).

Третий пункт важен: если сервис создан в панели Render руками, а не Blueprint'ом,
переменных окружения может не быть вовсе, и раньше в этом случае самопинг молча не
работал. Теперь достаточно один раз открыть сайт — дальше он поддерживает себя сам.

Состояние видно в панели администратора, раздел «Обслуживание»: адрес, откуда он взят,
время последнего пинга, число пингов и кнопка **«Проверить пинг»** для ручной проверки.

Важные оговорки:

- запрос на `127.0.0.1` входящим трафиком не считается, поэтому пинг идёт через
  внешний адрес — иначе Render всё равно усыпит сервис;
- если сервис всё же заснул (например, сеть моргнула), внутренний поток тоже стоит —
  разбудит только настоящий посетитель. Для полной надёжности в комплекте есть второй,
  внешний пинг — `.github/workflows/keepalive.yml` (задайте переменную репозитория
  `RENDER_URL` в **Settings → Secrets and variables → Actions → Variables**). Можно держать
  оба или удалить workflow — он необязателен.

Чего это стоит:

- у воркспейса **750 бесплатных часов инстанса в месяц**, спящий сервис часы не тратит;
  круглосуточный пинг съедает ~730 часов — то есть один такой сервис и ни одного больше;
- на плане Free без диска бодрствование заодно сохраняет данные между визитами,
  но **любой деплой всё равно обнуляет базу и файлы** — от этого спасает раздел ниже.

Выключить самопинг — `PYSPACE_KEEPALIVE=0` в панели Render. Интервал меняется
переменной `PYSPACE_KEEPALIVE_INTERVAL` (секунды, минимум 60).

Если в разделе «Обслуживание» написано «ждём первого запроса» — просто откройте сайт
в браузере. Если написано «выключен переменной PYSPACE_KEEPALIVE=0» — уберите эту
переменную в панели Render.

## 6. Автобэкап данных (бесплатно)

Чтобы проекты и пользователи не исчезали без платного диска, IDE умеет сама складывать
всё в один `tar.gz` и заливать в **приватный репозиторий GitHub**, а после деплоя —
скачивать обратно. Почему GitHub, а не Google Drive: нужен только один токен, без
OAuth-приложения и сервисного аккаунта, и репозиторий у вас уже есть.

### Настройка за две минуты

1. Создайте на GitHub **приватный** репозиторий для копий, например `pyspace-backup`
   (можно пустой, но с веткой `main` — просто поставьте галочку «Add a README file»).
2. **Settings → Developer settings → Personal access tokens → Fine-grained tokens →
   Generate new token**: доступ только к этому репозиторию, право
   **Contents: Read and write**, срок жизни на ваш вкус.
3. В Render → ваш сервис → **Environment** задайте:
   - `PYSPACE_BACKUP_REPO` = `ваш-логин/pyspace-backup`
   - `PYSPACE_BACKUP_TOKEN` = токен из пункта 2
4. Save changes → сервис перезапустится. В панели администратора появится блок
   «Обслуживание» с кнопками **Сохранить копию** и **Восстановить**.

### Как это работает

- каждые 15 минут (`PYSPACE_BACKUP_INTERVAL`) — копия, но **только если данные менялись**
  (сравнивается отпечаток файлов, сеть впустую не гоняется);
- ещё одна попытка — при остановке сервиса (перед редеплоем);
- при старте с пустым диском копия скачивается и распаковывается **до** миграций БД,
  так что после деплоя вы видите свои проекты на месте;
- в архив попадают база (`pyspace.db`) и все файлы проектов; `.packages`, `__pycache__`,
  `node_modules`, `.git` и `tmp` отбрасываются — пакеты pip легко поставить заново;
- предохранитель по размеру — 40 МБ (`PYSPACE_BACKUP_MAX_MB`); GitHub не любит файлы
  больше 100 МБ, для тяжёлых данных лучше платный диск;
- автовосстановление отключается переменной `PYSPACE_BACKUP_RESTORE=0`.

Проверка логики без сети: `python tests/test_backup.py` (архив → удаление данных →
восстановление).

Хотите именно Google Drive — это возможно (сервисный аккаунт + `PYSPACE_GDRIVE_*`),
но там нужно создавать проект в Google Cloud, включать Drive API и шарить папку на
сервисный e-mail — сильно больше шагов ради того же результата.

## 7. Запуск веб-приложений внутри IDE

Кнопка «Запустить сервер» на верхней панели (или `Ctrl+K` → «Запустить активный файл
как веб-сервер») поднимает Flask/FastAPI/любой другой сервер прямо из папки проекта и
открывает его в панели предпросмотра через обратный прокси `/live/<токен>`.
Остановка — той же кнопкой или командой «Остановить веб-сервер проекта».

Что важно знать:

- **Переключение автоматическое.** Если в файле есть `Flask(...)`, `FastAPI(...)`,
  `uvicorn.run(...)` или другой признак сервера, обычная кнопка «Запустить»
  (`Ctrl+Enter`) сама переключается в режим сервера и пишет об этом в вывод. Раньше
  такой файл упирался в таймаут `PYSPACE_RUN_TIMEOUT` и его гасили на середине.
- **Файл без `app.run()` тоже запустится.** Для FastAPI и для Flask, рассчитанного на
  gunicorn, IDE поднимает приложение сама: загрузчик `tools/webapp_boot.py` берёт файл
  по пути, достаёт из него объект приложения и отдаёт его `uvicorn` (FastAPI) или
  встроенному серверу Flask. Правки в коде не нужны. Имя файла может быть любым,
  включая `site.py`, `types.py` или `code.py` — конфликта со стандартной библиотекой нет.
- Если файл сам вызывает `app.run()` или `uvicorn.run(...)`, он запускается как есть,
  без подмены. Порт в этом случае возьмите из переменной `PORT`.
- Порт сервер должен брать из переменной `PORT` — IDE подставляет свободный порт сама.
- Через прокси проходит только HTTP. WebSocket внутри вашего приложения не проксируется.
- Cookie-сессия IDE называется `pyspace_session` и не передаётся в приложение проекта,
  поэтому ваше приложение может спокойно использовать своё cookie `session`.
- Переменные: `PYSPACE_ENABLE_WEBAPPS` (по умолчанию `1`), `PYSPACE_WEBAPP_LIMIT` (`3`),
  `PYSPACE_WEBAPP_BOOT_TIMEOUT` (`25` секунд на открытие порта).
- На плане Free одна инстанция и 512 МБ памяти: держать одновременно много серверов
  не стоит.

## 8. Что уже настроено внутри

- **Dockerfile**: `python:3.12-slim`, установлены `bash`, `git`, `curl`, `unzip`, `procps`,
  `tini`; работа под непривилегированным пользователем `pyspace`.
- **Сервер**: `gunicorn -k gevent -w 1 --timeout 0`, чтобы WebSocket-терминал держал
  соединение сколько нужно.
- **WebSocket**: `PYSPACE_GEVENT=1` включает gevent-патч в `wsgi.py`.
- **Health check**: `/healthz` — Render перезапустит контейнер, если ответа нет.
- **Терминал и предпросмотр** включены, **открытая регистрация выключена**
  (`PYSPACE_ENABLE_REGISTRATION=0`) — новых пользователей создаёт администратор
  в разделе «Админка». Хотите открытую регистрацию — поставьте `1`.

## 9. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Первый запрос открывается 30–50 секунд | план Free засыпает при простое; это ожидаемо |
| Терминал пишет «соединение потеряно» | проверьте `PYSPACE_ENABLE_PTY=1` и `PYSPACE_GEVENT=1` |
| Все данные пропали после деплоя | план Free без диска — включите автобэкап (раздел 6) или диск (раздел 4) |
| В панели админа «Копии данных: не настроены» | не заданы `PYSPACE_BACKUP_REPO` / `PYSPACE_BACKUP_TOKEN` |
| Копия не заливается: 403 или 404 | токен без права Contents: Read and write, неверный `логин/репозиторий` или в репозитории нет ветки `main` |
| Не пускает по логину администратора | переменные `PYSPACE_ADMIN_USER` / `PYSPACE_ADMIN_PASSWORD` заданы в Render? После их изменения сделайте Manual Deploy |
| Blueprint не видит файл | `render.yaml` должен лежать в корне репозитория, ветка `main` |
| Редактор или терминал не грузятся | они берутся с CDN (cdnjs, jsdelivr) — нужен доступ в интернет у браузера |
| «Сервер проекта не запущен» в предпросмотре | сервер остановлен или упал — нажмите «Запустить сервер» и посмотрите логи в панели «Вывод» |
| Сервер проекта не поднимается за 25 секунд | приложение слушает фиксированный порт вместо `PORT` либо долго ставит зависимости |
