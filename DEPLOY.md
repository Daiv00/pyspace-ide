# Деплой на Render

Задача: положить папку в репозиторий GitHub, один раз настроить Render, и дальше
любой `git push` сам обновляет сайт.

---

## 1. Залить папку на GitHub

Можно в существующий репозиторий (например `Daiv00/pyspace-ide`) или в новый.

```bash
cd pyspace-ide
git init
git add .
git commit -m "PySpace IDE 5.0"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

Если репозиторий уже существует и в нём старая версия — просто замените файлы новыми
и сделайте commit + push. Ветка должна называться `main` (она указана в `render.yaml`).

---

## 2. Создать сервис в Render (один раз)

1. Откройте [dashboard.render.com](https://dashboard.render.com).
2. **New → Blueprint**.
3. Выберите свой репозиторий с этой папкой. Render найдёт `render.yaml` сам.
4. Render покажет сервис `pyspace-ide` (Docker, план Free, регион Frankfurt).
5. Он попросит два значения, которых нет в файле (они помечены `sync: false`):
   - `PYSPACE_ADMIN_USER` — логин администратора, например `denis`;
   - `PYSPACE_ADMIN_PASSWORD` — пароль, минимум 8 символов.
   Остальные переменные, включая секрет сессии, Render создаст сам.
6. **Apply / Create resources** — начнётся сборка образа (5–8 минут в первый раз).
7. Когда статус станет `Live`, откройте адрес вида
   `https://pyspace-ide.onrender.com` и войдите под администратором.

Проверка здоровья сервиса: `GET /healthz` отвечает
`{"status":"ok","schema":1,"persistent":false}`.

---

## 3. Дальше — только push

`autoDeploy: true` уже стоит в `render.yaml`. Любой коммит в `main`:

```bash
git add .
git commit -m "правки"
git push
```

…запускает пересборку и деплой автоматически. Ничего в панели Render нажимать не надо.

---

## 4. Данные и план Free (важно)

На плане Free постоянный диск не подключается. Файловая система контейнера временная,
поэтому **при каждом деплое и при перезапуске (в том числе после «засыпания» сервиса)
база и файлы проектов обнуляются**. Пользователи, проекты и загруженные файлы исчезнут.

Внизу статус-бара IDE это видно: `диск: временный`.

Как жить с этим:
- скачивайте важные проекты кнопкой **Скачать проект (ZIP)**;
- восстановление — **Импорт ZIP в проект**.

### Включить постоянный диск (план Starter, платный)

Откройте `render.yaml`, раскомментируйте блок `disk` и смените план:

```yaml
    plan: starter          # было: free
    disk:
      name: pyspace-data
      mountPath: /data
      sizeGB: 5
```

и добавьте переменную:

```yaml
      - key: PYSPACE_DATA_DIR
        value: /data
```

После `git push` Render подключит диск, и статус-бар покажет `диск: постоянный`.

## 5. Что уже настроено внутри

- **Dockerfile**: `python:3.12-slim`, установлены `bash`, `git`, `curl`, `unzip`, `procps`,
  `tini`; работа под непривилегированным пользователем `pyspace`.
- **Сервер**: `gunicorn -k gevent -w 1 --timeout 0`, чтобы WebSocket-терминал держал
  соединение сколько нужно.
- **WebSocket**: `PYSPACE_GEVENT=1` включает gevent-патч в `wsgi.py`.
- **Health check**: `/healthz` — Render перезапустит контейнер, если ответа нет.
- **Терминал и предпросмотр** включены, **открытая регистрация выключена**
  (`PYSPACE_ENABLE_REGISTRATION=0`) — новых пользователей создаёт администратор
  в разделе «Админка». Хотите открытую регистрацию — поставьте `1`.

## 6. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Первый запрос открывается 30–50 секунд | план Free засыпает при простое; это ожидаемо |
| Терминал пишет «соединение потеряно» | проверьте `PYSPACE_ENABLE_PTY=1` и `PYSPACE_GEVENT=1` |
| Все данные пропали после деплоя | план Free без диска, см. раздел 4 |
| Не пускает по логину администратора | переменные `PYSPACE_ADMIN_USER` / `PYSPACE_ADMIN_PASSWORD` заданы в Render? После их изменения сделайте Manual Deploy |
| Blueprint не видит файл | `render.yaml` должен лежать в корне репозитория, ветка `main` |
| Редактор или терминал не грузятся | они берутся с CDN (cdnjs, jsdelivr) — нужен доступ в интернет у браузера |
